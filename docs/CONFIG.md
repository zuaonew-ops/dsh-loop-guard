# 配置参考

对象：`dsh-loop-guard` **v0.5.1**，源码快照 **`index.js` `d3041377d613d1c8` / 1987 行 / 89,041 B**（完整 sha256 `d3041377d613d1c88e674b199457b131422ac4b7eb2aca61ab4d56907339536f`）。所有默认值、范围、判据语义都取自插件源码 `index.js`（`DEFAULTS` / `resolveConfig` / `detectTrip`）与包内 `cordis.patch.yml`；§5.1 的容错表是在这个快照上**实测**出来的。

## 1. 配置的三层，谁覆盖谁

| 层 | 写在哪 | 什么时候读 | 优先级 |
|---|---|---|---|
| ① bundle 补丁 | 包内 `cordis.patch.yml` 里那一行的 `config:` | 宿主启动 / 该行重载 | 最低 |
| ② 设置文件 | `$DSH_HOME/loop-guard-settings.json`（`DSH_HOME` 未设 → `~/.dsh/loop-guard-settings.json`；可用 `settingsPath` 改） | **只在插件挂载时读一次** | 覆盖 ① |
| ③ 设置页 / `POST /loop-guard/config` | 内存 + 原子写回 ② | 立即生效 | 覆盖 ①② |

**由此推出的四条规则：**

1. **界面里改过的值，重启后仍然生效**（文件优先于 yml）。
2. **想回到 yml 的值**：删掉设置文件，再重启宿主。
3. **运行中直接改设置文件没有用**（只在挂载时读一次）。要么用设置页，要么重启。
4. **多开宿主会共用同一份设置文件**（路径只按 `$DSH_HOME` 定位，与 profile 无关），两边各自写盘会互相覆盖。本机实测到过一次：文件里是 `repeatMinChars: 500`，而运行中实例的内存里仍是 `1000`。

## 3. 每个键详解

### 3.1 `enabled`（默认 `true`）

- **语义**：`false` 时**三条监听一条都不装**，完全不干预 —— 不掐断、不改重试、不降档。
- **注意**：关掉后设置页**仍然可用**（你还能看到统计与最近触发，只是数字不再变化）。
- **什么时候动**：排障时想确认「问题是不是守卫引起的」——关掉对比一次。

### 3.2 `reasoningChunkLimit`（默认 `20000`，整数 ≥ 100）—— 规则 `chunk`

- **判据**：推理分片数 ≥ 本值 **且** 产出分片（文本 + 工具调用）**= 0**。
- **调小**：更早掐断分片洪水，但正常的长思考（一直只出思考、还没开始写正文）会更容易被切。
- **调大**：更宽容，但真洪水会烧更久。
- **实测依据**：真机循环尝试的推理分片数是 20,704 / 21,103 / 16,902 / 11,827 —— 取 20000 能拦住最大的几次，同时给正常长推理留余量。
- **注意**：它**只**在产出为 0 时才算数。模型只要吐了一个文本或工具调用分片，这条规则立刻不再适用（哪怕推理了十万片）。

### 3.3 `stallTimeoutMs`（默认 `180000` = 3 分钟，整数 ≥ 10000）—— 规则 `stall`

- **判据**：距上一个分片（**或起始时刻** —— 首块之前也算）≥ 本值。**不看产出**：沉默就是沉默。
- **调小**：网络慢、服务端排队、长工具调用前静默时可能误杀。
- **调大**：真卡死时要等更久才救。
- **实测依据**：真机的零分片空档是 **1.95 小时**与 **1.5 小时**，3 分钟离它们有两个数量级余量；正常调用里唯一一次 300 秒空档的尝试，末条是适配器自己的 `stream idle timeout after 300000ms`（早已判死）。
- **界面单位**：按**秒**填（默认 180 秒），宿主内部按毫秒记。

### 3.4 `noOutputMs`（默认 `600000` = 10 分钟，整数 ≥ 10000）—— 规则 `noOutput`

- **判据**：已耗时 ≥ 本值 **且** 产出分片 **= 0**。
- **⚠ 这是五条规则里最可能误杀的一条**：正常的长思考也会「产出为 0」。
- **调大**：如果你确实有「合法地思考十分钟以上才吐第一个字」的用法，**优先调大它**（比如 900000 = 15 分钟）。
- **实测依据**：
  - 真实调用时长分布（14,750 次有产出的调用）：p99 = 0.95 分钟、最长 **7.48 分钟**、**≥600 秒的 0 次**；零产出调用 16 次、最长 **3.39 分钟**。
  - 所以 600 秒这条线**高于全部观测样本**，观测误杀面 0；但**余量只有 1.34×**（600 ÷ 449 秒）。
- **它为什么存在**：真机发生过一次「5,450 个推理分片 / 260 秒 / 产出 0、且没有任何 ≥180 秒空档」的慢速渗流 —— `chunk`（片数不够）和 `stall`（没有空档）**都抓不到**，只能干等到 30 分钟。

### 3.5 `repeatWindowChars`（默认 `6000`，整数 1000–200000）—— 规则 `repeat`

- **语义**：重复检测的**观察窗口**，只看最近这么多字符（推理分片 + 文本分片；工具调用分片不参与），不累积整段历史。
- **调大**：能发现更长的循环周期，但 CPU 开销上升、判定更迟（因为要等更多字符）。
- **调小**：更快更省，但长周期循环可能看不出「行数远多于唯一行数」。
- **开销与节流**（`repeatRecheckCharsOf(W) = max(256, floor(W/32))`）：

  | 窗口 W | 指标重算间隔 |
  |---|---|
  | 6000（默认） | 256 字符（**未变**） |
  | 20000 | 625 字符 |
  | 60000 | 1875 字符 |
  | 200000 | 6250 字符 |

  除了按间隔节流，还有两次**额外补算**：**窗口刚满时补算一次**（只发生一次）、**流结束时补算一次**（这一次只判 `repeat` 规则，不会因为「恰好结束在零产出超时边界」而凭空多出误判）。
- **实测依据**：真机退化块里最高频行出现 2,931–3,332 次、唯一行占比 0.5%–3.8% —— 6000 字符足够看出循环，又不会把正常散文卷进来。

### 3.6 `repeatMinChars`（默认 `1000`，整数 500–`repeatWindowChars`）—— 规则 `repeat`

- **语义**：判据的**最低字符门槛**。窗口短于它就不做重复判定 —— 取代了早期「窗口必须满 `repeatWindowChars`」这个前置。
- **这是「灵敏度回退」开关**：**设成等于 `repeatWindowChars` 就退回旧语义（只判满窗）**。
- **调小**：短块退化能更早被抓到（默认 1000 已经能覆盖 2,029–4,521 字符的真退化短块）；但判定在小样本上做，噪声更大。
- **实测依据**：旧前置（必须满 6000）导致块长 < 6000 的 **7 个真退化短块永远不判**；改成 1000 后这 7 个 **7/7 命中**，而全语料误杀仍为 **0**。

### 3.7 `repeatMinLines`（默认 `30`，整数 5–5000）—— 规则 `repeat`

- **语义**：窗口内**非空行数**少于本值就不走「行判据」，而交给 k-gram 兜底。
- **调大**：只抓「很多行在重复」的形态。
- **调小**：单行/少行退化更容易落进片段兜底分支。
- **实测依据**：真机退化块的非空行数是 5,947–7,074 行（远超 30）；短块退化的 `19/8` 是 179 行。

### 3.8 `repeatCycles`（默认 `6`，整数 2–100）—— 规则 `repeat`

- **语义**：窗口（某个子窗）里**最高频那一行**至少要出现这么多次。
- **调小**：更早判定（2 就是「同一行出现两次」）。
- **调大**：要重复更多轮才算。
- **实测依据**：判据从旧写法「行数 ≥ 轮数 × 唯一行数」改成现在的「最高频那一行 ≥ 轮数」，因为旧写法会**真漏检**一条 376 行 / 唯一行占比 32.4% / `Let me go.` 出现 233 次的真实退化块。

### 3.9 `repeatUniqueRatio`（默认 `0.2`，0.01–0.9）—— 规则 `repeat`

- **语义**：窗口（某个子窗）内**唯一行占比**的上限，超过就不判。
- **调大**：更激进（更容易命中）。
- **调小**：更保守。
- **实测依据**：真机退化块的唯一行占比是 **0.5%–3.8%**；而正常文本里最接近阈值的是 **0.2574**（一个 markdown 围栏块）→ 默认 0.2 对最近一次误杀有 **1.29×** 余量。

### 3.10 `repeatGramRatio`（默认 `0.10`，0.01–0.9）—— 规则 `repeat` 的片段兜底

- **语义**：当整窗非空行数 **< `repeatMinLines`**（也就是几乎只有一行）时，行判据**结构上不可能命中**（单行块的「唯一行占比」恒为 1.0），于是改用：把子窗按 **8 个字符**切成**不重叠**片段（先做**空白压缩**），**唯一片段占比** ≤ 本值就判退化。
- **⚠ 调高会更容易误杀长单行自然语言**：实测中文自然散文单行约 **0.36**、英文约 **0.45**，而真退化单行只有 **0.007–0.009**。
- **实测依据**：默认值从 0.35 降到 0.10 —— 0.35 时中文散文单行 0.3613 只剩 3% 余量；降到 0.10 后对两个真退化单行有 **10.7× / 14.9×** 余量，对最低的非退化样本（0.1760）有 **1.76×** 余量，全语料误杀仍为 **0**。
- **为什么必须做空白压缩**：否则深缩进代码会产生大量相同的「8 个空格」片段，在小子窗上足以把唯一率压到阈值以下 —— 那是**排版**重复，不是内容重复。实测同一段深缩进代码：压缩前唯一率 0.6575，压缩后 1.0000。

### 3.11 `attemptBudgetMs`（默认 `1800000` = 30 分钟，整数 ≥ 10000）—— 规则 `absolute`

- **判据**：已耗时 ≥ 本值，**不看产出**。
- **调小**：一直在正常出文本的超长任务会被硬切（实测有一条正常长流会在 12 分钟处被切，所以早期更小的值被放弃了）。
- **调大**：真循环的兜底时间变长。
- **实测依据**：观测里有产出的调用最长 **7.48 分钟**、**≥30 分钟的 0 次**。这是观测上界，不是保证。

### 3.12 `maxGuardedRetries`（默认 `1`，整数 0–5）

- **语义**：守卫掐断后，同一个 `turn/step` 允许宿主**纠正重试**几次。用完之后守卫返回「终结」，不再重试。
- **`0`** = 拦到就终结（不重试）。
- **调大** = 多给几次机会，但每次都可能再烧时间。
- **只作用于本插件自己的失败码**：`LOOP_GUARD`。其它失败码（网络超时、传输错误……）一律交给宿主默认策略，守卫绝不干预。
- **真机样本**：一次「5,450 片 / 260 秒 / 零产出」的尝试被掐断后，**1 次**纠正重试就恢复了正常产出（73 秒后该步产出 `reasoning + text + tool-call + tool-call` 并正常收尾）。

### 3.13 `lowerEffortOnRetry`（默认 `true`）

- **语义**：纠正重试时，把该 agent 下一次请求的 `reasoningEffort` **降一档**（阶梯 `max → high → low → off`）。只在最近 **120 秒**内循环过的 agent 上生效。
- **当前档位不在这个阶梯里时是空操作**（宁可不降，也不瞎猜档位名）。所以某些 provider/model 上你**看不到任何效果**，这不是 bug。
- **关掉它**：就没有「给它一条走得通的路」这第三道防线。

### 3.14 `settingsPath`（默认 `''`，只能写 yml）

- 留空 = `$DSH_HOME/loop-guard-settings.json`（`DSH_HOME` 未设 → `~/.dsh/loop-guard-settings.json`）。
- 填了就用填的路径。写盘失败**只告警不抛错**（不会因为写不了盘把宿主弄崩）。

### 3.15 `maxRecent`（默认 `50`，整数 1–500，只能写 yml）

- 设置页「最近触发」保留多少条（每条含 时间 / turn·step / 推理分片数 / 已耗时 / 产出分片数 / 规则名 / 消息）。

### 3.16 `debug`（默认 `false`，只能写 yml）

- `true` 时把每次拦截写进宿主日志。**排障用**：想知道「到底有没有拦、走的哪条规则」时打开它，或直接看设置页的「最近触发」。

## 4. 规则 `repeat` 的判据全貌（最容易被误解的一条）

窗口 = 最近 `repeatWindowChars` 个字符。判据**不是**看整个窗口，而是在窗口上枚举**子窗**：

- 子窗尺度 `S = repeatMinChars × 2^k`，**再加上窗口本身**（默认就是 1000 / 2000 / 4000 / **6000**）；
- 每个尺度取长度为 `S` 的**所有后缀子窗**，步长 `floor(S/2)`；
- 对每个子窗算指标，最后取**最坏**的那一个 —— 所以「前半段正常、后半段开始循环」不会被前面的正常内容稀释掉。

然后：

```
行判据  = 窗口长度 ≥ repeatMinChars
          且 某子窗 非空行数 ≥ repeatMinLines
          且 该子窗 唯一行占比 ≤ repeatUniqueRatio
          且 该子窗 最高频那一行出现次数 ≥ repeatCycles

片段兜底 = 窗口长度 ≥ repeatMinChars
          且 整窗非空行数 < repeatMinLines
          且 某子窗 8 字符不重叠片段唯一率（空白压缩后） ≤ repeatGramRatio
```

两个分支互斥（按「整窗非空行数 < `repeatMinLines`」分流）。

**误杀余量（必须分口径看，不能只报一个数）：**

| 口径 | 正常文本最接近阈值的值 | 阈值 | 余量 | 来源 |
|---|---|---|---|---|
| 全语料非退化块 · 片段兜底 | 0.4032 | 0.10 | **4.03×** | `_verify-repeat-corpus-v55.log` |
| 全语料非退化块 · 行判据 | 0.2574（markdown 围栏块） | 0.20 | **1.29×** | 同上 |
| 「常量模板 + 只变计数器」形状 | 0.1060 | 0.10 | **1.06×** | `cordis.patch.yml` |
| 同形状的子窗相位噪声 | 同一文本平移 0–255 字符，最差子窗在 0.1060–0.1720 漂移 | — | **±30%** | 同上 |

**结论**：语料里 **0 误杀**是真的（6,000+ 个非退化块 0 命中）；但「正常文本至少离阈值 3.92×」**不成立** —— 灵敏度在 v0.5 提高了（分段取最坏值恒 ≤ 整窗值）。要退回旧语义：`repeatMinChars = repeatWindowChars`。

## 5. 校验与报错

三处输入源的严格程度不同：**`cordis.patch.yml` 最严（抛错）**、**设置文件最宽（退回 yml 的值 + 告警）**、**设置页与接口在中间（本地提示 / HTTP 400）**。

| 情况 | 行为 |
|---|---|
| `cordis.patch.yml` 里写了不存在的键 | **抛错并点名**（列出可用键），这一行加载失败 |
| `cordis.patch.yml` 类型不对 | 抛错：`必须是 boolean` / `必须是有限数字` / `必须是 string` |
| `cordis.patch.yml` 数字越界 | 抛错并给出范围（例：`config.reasoningChunkLimit 必须 >= 100`） |
| `cordis.patch.yml` 里 `repeatMinChars > repeatWindowChars` | 抛错 |
| **设置文件**：单键数值越界或不是整数 | **忽略该值 → 退回 `cordis.patch.yml` 的值，并打一条告警**；**不抛错** |
| **设置文件**：`repeatMinChars > repeatWindowChars`（跨字段，**合并后**判定） | **夹紧到窗口大小 + 告警**。两条路径都走这里：① 单键本身越界（门槛 20000 @ 窗口 6000）；② 单键各自合法但合起来越界（门槛 5000 + 窗口 4000）。**判越界看的是「生效窗口」，不是出厂默认的 6000**（见 §5.1-B） |
| **设置文件**：不是合法 JSON / 内容不是对象 | **告警** + 忽略整个文件（退回 yml） |
| **设置文件**：有当前版本不认识的键 | **静默丢弃该键**（不告警） |
| **设置文件**：类型不对（例如数字写成字符串） | **静默丢弃该键**（不告警） |
| 设置页里填了非法值 | **只在本页提示，不发请求**（11 条针对性文案，中英双语） |
| `POST /loop-guard/config` 提交未知键 | `400` + `unknown-key` |
| `POST /loop-guard/config` 提交的类型/范围不对 | `400` + `bad-type` / `bad-range` |
| `POST /loop-guard/config` 合并后 `repeatMinChars > repeatWindowChars` | `400` + `bad-range`（用**合并后**的值判定，所以只提交 `repeatMinChars=5000` 而窗口仍是 4000 也会被拒） |

### 5.1 设置文件容错实测表（源码快照 `index.js` `d3041377d613d1c8` / v0.5.1）

用真的 `apply()` + 桩上下文 + **临时**设置文件跑出来的 **20 组用例**，**全部不抛错**。

**A. 通用容错（15 组）**

| 设置文件内容 | 结果 | 该键最终生效值 | 告警 |
|---|---|---|---|
| 文件不存在 | OK | 默认值 | 无 |
| 坏 JSON | OK | 退回 yml 的值 | 有（1 条） |
| 内容不是对象（数组） | OK | 退回 yml 的值 | 有（1 条） |
| 未知键 `foo` | OK | 该键被丢弃 | **无**（静默） |
| 类型错 `reasoningChunkLimit: "20000"` | OK | 退回 yml 的值 | **无**（静默） |
| 类型错 `enabled: "true"` | OK | 退回 yml 的值 | **无**（静默） |
| 越界 `reasoningChunkLimit: 50` | OK | **20000**（yml 的值） | 有：`设置文件里的 reasoningChunkLimit 不合法，已退回 yml 的值：config.reasoningChunkLimit 必须 >= 100` |
| 越界 `maxGuardedRetries: 99` | OK | **1** | 有（同格式） |
| 越界 `repeatUniqueRatio: 5` | OK | **0.2** | 有（同格式） |
| 非整数 `repeatCycles: 6.5` | OK | **6** | 有（同格式） |
| 合法 `repeatMinChars: 5000`（窗口 6000） | OK | **5000 生效** | 无 |
| 跨字段 `repeatMinChars: 5000` + `repeatWindowChars: 4000` | OK | `repeatMinChars` **夹紧为 4000** | 有：`…已夹紧到窗口大小` |
| 坏值 `reasoningChunkLimit: 50`，同时 **yml 里写了 500** | OK | **500**（证明退回的是 **yml 的值**，不是出厂默认） | 有 |
| 三个坏值同时出现 | OK | 三个全部退回 | **三条**告警（一个坏键一条） |
| 坏值 + 跨字段同时出现 | OK | 两处都处理 | 两条告警 |

**B. 「门槛 vs 窗口」专表（5 组，逐键校验基准修复后）**

关键区分：**判越界要看「生效窗口」，不是出厂默认的 6000**。下表里的「生效窗口」= `cordis.patch.yml` 里写的窗口（没写就是默认 6000）。

| 设置文件内容（yml 里的窗口） | 门槛 vs 生效窗口 | 结果 | 生效值 | 告警 |
|---|---|---|---|---|
| `repeatMinChars: 20000`（yml 窗口 **30000**） | 门槛 **≤** 生效窗口 → **合法** | OK | `repeatMinChars=20000`、`repeatWindowChars=30000`，**都生效** | **无** |
| `repeatMinChars: 5000`（yml 窗口 **30000**） | 门槛 ≤ 生效窗口 | OK | **5000 生效** | **无** |
| `repeatMinChars: 20000`（yml 窗口 **200000**，上限） | 门槛 ≤ 生效窗口 | OK | **20000 生效** | **无** |
| `repeatWindowChars: 30000` + `repeatMinChars: 20000`（两个键都在设置文件里） | 门槛 ≤ 生效窗口 | OK | **20000 / 30000 都生效** | **无** |
| `repeatMinChars: 20000`（yml 窗口 **6000**） | 门槛 **>** 生效窗口 → 真越界 | OK | `repeatMinChars` **夹紧为 6000** | 有：`repeatMinChars (20000) 大于 repeatWindowChars (6000)，已夹紧到窗口大小` |

> **这一栏是修出来的**：早先版本逐键校验时拿**出厂默认窗口 6000** 当基准，于是「yml 把窗口调大、用户在设置页把门槛也调大」这个**合法**组合会被判非法、门槛被悄悄退回 yml 的值（界面刚接受的值自己消失了）。现在基准窗口取**上限**，跨字段不变量只由「合并后」那一段判一次。

**四条要点**：

1. **设置文件里写什么都不会让插件挂载失败**，设置页一定打得开 —— 这是「文件是外部输入（手改、跨版本降级）」这个前提下的正确语义。
2. 告警**一个坏键一条**，且只有一个 `dsh-loop-guard: ` 前缀。
3. **单键本身越界**（例如 `reasoningChunkLimit: 50`）→ 忽略该值、**退回 `cordis.patch.yml` 的值**（若 yml 没写就是出厂默认值）。
4. **单键合法但合并后越界**（门槛 > 生效窗口）→ **夹紧到窗口大小**（不是退回 yml 的值）。两条路径都会告警，只是文案不同。

## 6. HTTP 接口参考

三个端点都在 `/loop-guard` 前缀下，统一信封：`{ok:true, value}` / `{ok:false, error:{code, message}}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/loop-guard/state` | 返回 `enabled` + `config`（12 键）+ `stats` + `recent` |
| `POST` | `/loop-guard/config` | 提交 13 个可改键的**子集**；空 body 视为 `{}`（等于只写盘一次）；成功返回改后的 12 键 |
| `POST` | `/loop-guard/reset` | 统计清零（`attempts` / `guarded` / `retriesAllowed` / `terminalStops` / `savedMs` / `byRule` / `recent`），返回清零后的 `stats` |

**三道安全闸**（`/loop-guard` 下所有路径统一过）：

| 闸 | 不满足时 |
|---|---|
| `Sec-Fetch-Site: cross-site` | `403` + `cross-site` |
| `Origin` 存在但与本机不同源 | `403` + `bad-origin`。**`Origin` 缺失时放行**（所以 `curl` 能用） |
| `POST` 的 `content-type` 不是 `application/json` | `415` + `unsupported-media-type` |

**其它状态码**：请求体 > 64 KiB → `413` + `body-too-large`；body 不是合法 JSON → `400` + `bad-json`；路径对但方法不对 → `405` + `Allow` 头；路径不存在 → `404` + `not-found`。

**为什么需要这三道闸**：DSH 的 webServer 契约是 `{kind, path, handler}`，**没有全局 Origin/CSRF 防护**，插件路由也不在 GUI 的登录门后面。没有闸的话，任意网页都能用 `content-type: text/plain` 发跨站简单请求打到这里并让服务端真的执行。

## 7. 常见调参场景

| 你想要的 | 怎么配 |
|---|---|
| **默认就行** | 什么都不用改 |
| 我有超长思考（十几分钟才出第一个字） | `noOutputMs` 调大（如 `900000`），或调到很大等于关掉这一档 |
| 我嫌它太激进 / 误杀过 | ① `noOutputMs` 调大；② `repeatMinChars` 设成等于 `repeatWindowChars`（退回旧语义）；③ 临时 `enabled: false` 对比 |
| 我嫌它太迟钝（真循环烧太久） | `reasoningChunkLimit` 调小、`noOutputMs` 调小、`stallTimeoutMs` 调小；但每一条都在拿误杀率换速度 |
| 我要彻底关掉重试干预 | `maxGuardedRetries: 0`（拦到就终结） |
| 我不想让它改我的推理档位 | `lowerEffortOnRetry: false` |
| 我在排障，想看每次拦截 | `debug: true`（写宿主日志）+ 设置页「最近触发」 |
| 我的会话有超长任务，30 分钟不够 | `attemptBudgetMs` 调大（比如 `3600000` = 60 分钟） |
| 我完全不想让它动手 | `enabled: false` |

## 8. 恢复默认值

| 场景 | 做法 |
|---|---|
| 只想恢复某几个键 | 在设置页里改回默认值，或在 `cordis.patch.yml` 里删掉那几个键后重载该行（注意：设置文件仍然优先，所以要么同时删文件，要么用界面改） |
| 想完全回到 `cordis.patch.yml` 的值 | 删掉设置文件 + 重启宿主 |
| 想完全回到插件出厂默认 | 删掉设置文件，并把 `cordis.patch.yml` 里那一行的 `config` 留成 `{}`，然后重启 |
